## 1. Transaction Queue vs Portfolio Transactions

### Design Clarification

#### **Transaction Queue Tab**
**Purpose**: Displays pending trades that the **AI Agent** plans to execute autonomously

**Characteristics**:
- Trades generated by AI analysis and recommendations
- Not yet submitted to Alpaca
- User can review, approve, or reject before execution
- **Queue Management**: 
  - Add to queue
  - Remove from queue
  - Modify before execution
  - Set priority/timing
- **Workflow**: Research → AI Analysis → Transaction Queue → User Approval → Execute → Portfolio

**Example Use Cases**:
- AI identified AAPL as undervalued → adds BUY order to queue
- User reviews AI's recommendation
- User approves → trade executes → appears in portfolio
- User rejects → removed from queue

#### **Paper Portfolio / Live Portfolio Tabs**
**Purpose**: Display **executed transactions** and current positions

**Characteristics**:
- Shows all orders submitted to Alpaca (filled, pending, or rejected)
- Includes both:
  - **Manual trades**: User-initiated via "Execute Trade" button
  - **AI trades**: Approved from Transaction Queue and executed
- **Order States**:
  - `pending`: Submitted, awaiting market open
  - `filled`: Completed
  - `partially_filled`: Partially completed
  - `rejected`: Rejected by broker
  - `canceled`: User or system canceled

**What Shows Here**:
✅ All manual trades (immediate execution)  
✅ All Transaction Queue trades (after approval & execution)  
✅ Pending orders (market closed)  
✅ Filled positions  
✅ Transaction history

## 2. Complete Transaction Flow Diagram

```
┌─────────────────────────────────────────────────────────────┐
│                    USER MANUAL TRADING                       │
│                                                              │
│  User clicks "Execute Trade" → Enters symbol/quantity       │
│                    ↓                                         │
│              Immediately submits to Alpaca                   │
│                    ↓                                         │
│         Appears in Paper/Live Portfolio tab                  │
│              (pending or filled)                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                   AI AUTONOMOUS TRADING                      │
│                                                              │
│  AI Research → Identifies Opportunity → Generates Trade      │
│                    ↓                                         │
│              Added to Transaction Queue                      │
│              (NOT yet sent to Alpaca)                        │
│                    ↓                                         │
│         User reviews in Transaction Queue tab                │
│                    ↓                                         │
│         User approves ✅  OR  rejects ❌                     │
│                    ↓                                         │
│  If approved: Submit to Alpaca → Portfolio tab               │
│  If rejected: Remove from queue (no trade)                   │
└─────────────────────────────────────────────────────────────┘
```

## 3. Tab Responsibilities Matrix

| Feature | Transaction Queue | Paper Portfolio | Live Portfolio |
|---------|------------------|-----------------|----------------|
| **AI-generated trades** | ✅ Pending approval | ✅ After execution | ✅ After execution |
| **Manual trades** | ❌ Bypass queue | ✅ Immediate | ✅ Immediate |
| **Filled orders** | ❌ | ✅ | ✅ |
| **Pending orders** | ❌ | ✅ | ✅ |
| **Order history** | ❌ | ✅ | ✅ |
| **Current positions** | ❌ | ✅ | ✅ |
| **User approval** | ✅ Required | ❌ Auto-display | ❌ Auto-display |
| **Modify before exec** | ✅ Yes | ❌ Too late | ❌ Too late |

## 5. Pending Orders Feature

### Requirements:
Users need to see orders that are submitted but not yet filled (market closed).

### Backend Endpoint Needed:
```python
@router.get("/alpaca/paper/orders")
async def get_paper_orders(status: str = "all"):
    """
    Get orders from paper trading account
    
    Args:
        status: 'open', 'closed', 'all'
    
    Returns:
        List of orders with details
    """
```

### Frontend Display (Paper Portfolio):
```javascript
// Add to PaperPortfolio.js
const [orders, setOrders] = useState([]);

// Fetch orders
const fetchOrders = async () => {
  const response = await fetch(`${API_BASE_URL}/api/v1/alpaca/paper/orders?status=open`);
  const data = await response.json();
  setOrders(data.orders);
};

// Display in UI
{orders.length > 0 && (
  <div className="pending-orders">
    <h4>Pending Orders (Market Closed)</h4>
    {orders.map(order => (
      <div key={order.id}>
        {order.side} {order.qty} shares of {order.symbol}
        Status: {order.status}
      </div>
    ))}
  </div>
)}
```

## 7. Database Schema

### Trades Table
```sql
CREATE TABLE trades (
    id SERIAL PRIMARY KEY,
    source VARCHAR(20) NOT NULL, -- 'manual' or 'ai_queue'
    symbol VARCHAR(10) NOT NULL,
    side VARCHAR(4) NOT NULL, -- 'buy' or 'sell'
    quantity INTEGER NOT NULL,
    order_type VARCHAR(10), -- 'market', 'limit'
    status VARCHAR(20), -- 'queued', 'pending', 'filled', 'rejected'
    alpaca_order_id VARCHAR(50), -- null until submitted
    ai_confidence DECIMAL(5,2), -- for AI trades
    ai_reason TEXT, -- for AI trades
    created_at TIMESTAMP DEFAULT NOW(),
    submitted_at TIMESTAMP, -- when sent to Alpaca
    filled_at TIMESTAMP, -- when filled
    user_approved BOOLEAN DEFAULT FALSE,
    approved_at TIMESTAMP
);
```
